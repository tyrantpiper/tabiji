## 1. Problem Statement & Root Cause (問題陳述與根本原因剖析)

### 1.1 痛點 1：滑動刪除誤觸 (Swipe-to-Delete Misfire)
- **問題**：使用者在手機直向滑動瀏覽時間軸時，手指微小橫向位移（`offset.x < -35`）即會觸發 `framer-motion` 的 `drag="x"`，導致紅色垃圾桶刪除抽屜經常無預警彈出，嚴重干擾滾動體驗。
- **解法**：徹底移除 `SortableTimelineCard.tsx` 中的橫向手勢攔截與滑動刪除層。活動刪除回歸右上角「三點選單 (`...`)」與已實作之「5 秒 Undo 安全 Toast 防護機制」。

### 1.2 痛點 2：卡牌橫向長度過短 (Card Horizontal Compression)
- **根本原因**：
  1. **獨立左側時間軸欄位佔位**：時間與序號置於獨立左欄，佔據了 `56px (w-14)` + `16px (gap-4)` = 72px 橫向空間。
  2. **時間軸外容器過度留白**：`ItineraryTimeline` 使用 `px-5` (40px 邊距)，而上方儀表板與天氣為 `px-4` (32px)，產生凹陷感。
  3. **縮圖過度避讓**：縮圖右側硬編碼了 `mr-8` (32px) 避開浮動的三點按鈕，進一步壓縮中央文字至僅剩約 126px。
- **解法**：
  1. 將「時間、序號、拖曳手把」全面**收編進卡片內部頂部膠囊列**。
  2. 卡片本體擴展為 **100% 滿版寬度**，外層容器與上方儀表板/天氣對齊為 `px-4`。
  3. 解除縮圖 `mr-8` 限制，三點按鈕置於頂部標頭右側，使文字可視寬度暴增 +60px 以上。

│                                                             │

### 2.1 頂部時序膠囊 (Top Header Pill)
- **左側手把 (⠿)**：整合 `@dnd-kit` 之 `attributes` 與 `listeners`，作為明確的拖曳抓取錨點。
- **序號標章 (①)**：黑色高對比圓形序號徽章 (`w-5 h-5 rounded-full bg-slate-900 text-white text-[10px]`)。
- **時間顯示 (09:00)**：`font-mono text-xs font-bold text-slate-700 dark:text-slate-200`。
- **分類標籤**：`[ 🍽️ Food ]` / `[ 🔒 Private ]`，與膠囊並列流暢排版。
- **右上角操作**：三點按鈕 (`...`) 乾淨獨立於標頭右側。

### 2.2 內容區 (Main Body)
- 標題與內文享有卡片全橫向寬度。
- 右側 80px (`w-20 h-20`) 圓角縮圖取消 `mr-8`，緊貼卡片內邊距。

## 3. Edge Cases & Boundary Conditions (邊界條件與防禦規則)

| 情境 | 表現 | 防禦機制 |
| :--- | :--- | :--- |
| **Header 備註卡片 (00:00)** | 非景點活動，僅為全天通知 | 頂部膠囊改為 `[ 💡 INFO ]`，隱藏序號與拖曳手把，禁止拖曳排序 |
| **無照片行程** | 活動未上傳或未配圖 | 標題與說明文字享有 100% 卡片內寬度，右側無留白縫隙 |
| **高頻滾動與觸控衝突** | 手指垂直快速翻頁 | 徹底拔除 `framer-motion` `drag="x"`，原生滾動 0 掉幀、0 誤觸 |
| **長按拖曳排序** | 手指長按 250ms 排序 | 保留 `dnd-kit` 感應器，拖曳手把與長按卡片皆能啟動排序 |
